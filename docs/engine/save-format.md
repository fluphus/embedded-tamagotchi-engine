# 存档与迁移边界

## v10 显式格式

所有整数小端，绝不依赖 sizeof(State)、布局、bool ABI 或主机编译器。
包身份：Artoria `0x41525452`，Sprout `0x53505254`。版本 10；扩展独立版本当前均为 1。

| 字节偏移 | 长度 | 含义 |
| --- | --- | --- |
| 0 | 4 | ASCII PETE |
| 4 | 2 | 格式版本 10 |
| 6 | 1 | full 标记 0/1 |
| 7 | 1 | 保留 0 |
| 8 | 4 | 内容包 ID |
| 12 | 4 | sequence |
| 16 | 4 | savedAt 日历秒 |
| 20 | 2 | payload 长度，总长度减 24 |
| 22 | 2 | 整条记录校验值，计算时本字段为 0 |
| 24 | 2 | 稳定形态 ID |
| 26 / 28 | 各 2 | 有符号健康值 / 严肃值 |
| 30 | 2 | 空闲分钟余数 |
| 32 / 36 / 40 / 44 | 各 4 | 暂停截止、上次有效 poke、出生、上次互动 epoch |
| 48 | 2 | age_days |
| 50 | 1 | stage |
| 51 | 2 | 内容扩展版本 |
| 53 | 1 | 内容扩展长度 |
| 54 | 64 | 内容包编码扩展；未用部分必须 0 |
| 118 | 42 | 保留 0，宠物记录截止 160 |
| 160 | 1 | 完整记录图鉴数量 |
| 161 | 64 | 32 个 u16 稳定 ID；未用部分必须 0 |
| 225 | 3 | 保留 0，完整记录截止 228 |

校验沿用 rotate/add 算法：初值 0xffff，每字节 XOR、循环左移 3、加原字节，均截断 16 位。
v10 覆盖整条记录；v9 仅覆盖旧 PetState 56 字节。算法不是密码签名，不提供防伪能力。

解码严格检查长度、magic、版本、包身份、checksum、保留字节、已知 ID、重复图鉴、扩展版本/长度/值。
失败不修改输出。编码也先验证内容包状态。未知包不会按默认包解释。

## v9 证据与迁移

`tools/engine/generate_v9_fixtures.py` 从 Git 基线 `448dbe158595c1db9f1d2fc37caa15810c53de1c` 提取原 game_state.h 和 gallery.h，
使用 Xtensa ESP32-S3 g++ 8.4.0 编译静态聚合对象，通过目标 objcopy 提取专用 ELF sections，得到布局及原始字节。
未编译或转储主机 PetState。manifest.json 保存源头 SHA256、编译器、参数、所有偏移和样本 SHA256。
工具链位置可通过 XTENSA_PREFIX 覆盖（含末尾 `xtensa-esp32s3-elf-`）。

目标证据：PetState=56、SaveHeader=16、DailyFeedState=12、GalleryData=12、DeviceState=12；旧宠物/完整记录为 72/84。
样本含白成体、Nobu、黑狮、白狮、图鉴、设备状态及串门设备状态。
这些是原始头文件与目标工具链生成的测试夹具，不是真实设备旧档；没有采样运行时 padding、现实损坏或真实 NVS 掉电。
头部/宠物 padding 来自目标对象，校验按原算法填入；迁移按证实的偏移读取，不要求 padding 为 0。

content/artoria/v9.h 仅承担 Artoria v9 解码迁移。保留旧枚举 0..11；未知版本、非法长度、坏校验、未知枚举/非法 bool 拒绝。
旧 v9 校验未保护头和图鉴，迁移不能恢复旧格式本来没有的完整性证据。
Sprout 拒绝 Artoria 旧档；v10 两包也互相拒绝。老固件不支持读取 v10，未声称降级兼容。

## NVS 与失败保护

- 保留 namespace 与三槽、活动槽对/序号策略。新键 s0/1/2_v10 是完整单键记录；s0/1/2_stage 为有限暂存。
- 写入先编码、写 stage、读回逐字节验证，再原子替换 committed 键；任一步失败不推进序号，粘滞重试目标槽。
  stage 永不作启动恢复来源。原子键替换是 KeyValue/Preferences 适配契约，主机故障注入验证契约下的保护；真实掉电未实测。
- 原 s*_hdr/dat/gal 只读。仅当相应 v10 键不存在时尝试 v9；如果 v10 已存在但坏/未知，不回退同槽更旧旧档。
  跨槽按现有活动对/序号回退有效记录，串门时冻结主人槽不作访客回退。
- 新 gallery_v10 显式包身份/u16版本1/数量/稳定ID/校验；device_v10 固定19字节，含版本1、包身份、epoch、轮次、串门标志、主人槽、开始时间和校验。
  原 gallery/dev_state 分别按目标12字节格式读取，非法长度拒绝。slot_cfg 保留既有4字节协议，现按字节编码。
- 启动存在任何原始存档键时，先置 recoveryRequired。仅验证加载/明确合法导入或显式删除成功才解除。
  全坏、未知包/版本或坏设备态/图鉴时禁止自动保存、图鉴和设备态写入；不静默清档或用新宠覆盖。
- 主人恢复失败保留串门及主人槽并报告错误，不沿用原代码丢弃主人槽的失败分支。
  这是任务书要求的数据保护变化，不是新玩法。

## 集中审计修订：自动写保护与导入中断

hasSave包括旧/新图鉴、设备态及未完成导入标记，只有附属数据也不会自动初始化覆盖。
自动写入逐槽排除未知/损坏记录和冻结主人，即使另一个槽加载成功也不解除这些槽的保护。
完整COMMIT各写入步骤检查结果，失败保留部分记录并持久锁写；成功才提交RAM和输出restored/Visit started。
import_guard为6字节magic/status/owner/version/checksum小标记；它不是替代v10的宠物格式，也不是全局事务。
失败恢复步骤、测试矩阵及限制见 [targeted-audit.md](targeted-audit.md)。v9/v10宠物编码、校验和资源未在本轮修改。


## 结束串门恢复保护

`restoreVisitOwner` 复用同一 `import_guard` 协议，覆盖活动槽对、非串门设备态及最终主人槽写入，全部完成才清 pending。新增 `owner_restore` 保存恢复前的有界规范记录：v10 来源逐字节保留，v9 来源经既有迁移转为 v10 且原 v9 键不变；不参与自动加载/轮转，成功后也保留到下一次明确恢复或明确清档。hasSave包括这个保留键。最后写回主人成功而完成标记失败时，仍启动Recovery，原始副本不丢失。没有改宠物/设备记录版本、布局、校验或串口协议。定向证据及人工恢复限制见 [visit-restore-audit.md](visit-restore-audit.md)。


## 最终补充验收的写入上限和恢复命令

sequence 为 uint32，值到 UINT32_MAX 后禁止生成新的自动/手动记录，避免回绕到0造成新旧排序错误；读取和导出有效记录仍可用。明确导出、恢复擦除、再导入可开始新的序列。
`SAVE_EXPORT_OWNER` / Python `export --slot -1` 可在恢复锁下导出合法 `owner_restore`；若源为仅宠物记录，导出缓冲区升级为带当前形态最小图鉴的完整备份，原NVS副本不改，保证空设备也能恢复主人。普通启动不清理副本。存档编码版本、v9字段和校验本轮未改变。详见 final-supplementary-acceptance.md。
